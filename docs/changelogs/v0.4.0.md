# v0.4.0

## Release Date

2026-11-24

## Overview

Adds task chains (`sap.dwc.taskChain`) as a design object type: the client can read and delete them, check whether one exists, and import task-chain CSN files. Catalyst-CLI uses this for `catalyst bdc delete|read|exists --object-type task-chain`.

## Breaking Changes

None. The changes are additive.

## What's New

### Task Chains

- **`readTaskChain(name)`** and **`deleteTaskChain(name)`** on the client. Delete sends `deleteAnyway=true`, like every other type.
- **`objectExists('task-chain', name)`**: `task-chain` is added to `DATASPHERE_OBJECT_TYPES` (endpoint `taskchains`, CSN key `taskchains`).
- **The endpoint is UNVERIFIED.** `GET|DELETE /dwaas-core/api/v1/spaces/{space}/taskchains/{name}` follows the naming of the other five types. Each endpoint is SAP's `datasphere objects` type name with the hyphen dropped (`local-tables` becomes `localtables`, `task-chains` becomes `taskchains`), and for flows the endpoint matches the CSN top-level key (`taskchains`). SAP's CLI reads its paths from the tenant's discovery document, so this could not be confirmed offline. If the path is wrong, read and delete return the tenant's 404, and `objectExists` returns `false`.

### Import

`importCsn` already imported task-chain files: it posts the whole CSN unchanged. It now also counts `taskchains` in its debug line and includes task-chain names when it polls for object IDs after an asynchronous (background) import. Before this change, a task-chain-only file whose import went async was never deployed.

## Technical Details

- New `core/operations/task-chain/` with `read` and `delete`, exported from the operations barrel.
- `CsnTaskChain` type (`kind: 'sap.dwc.taskChain'`, otherwise permissive), exported from the package entry. `CsnFile` gains `taskchains?`.
- Tests: a new unit test, `objectTypes.test.ts`, checks the endpoint naming rule for every registered type and the task-chain entry. The integration test `endpointDiscovery.test.ts` gains a task-chain endpoint check, plus a read of an existing chain when `DSP_TEST_TASK_CHAIN` is set. `safeDelete` handles `task-chain`. The integration tests need a live tenant and were not run.
