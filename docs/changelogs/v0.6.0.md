# v0.6.0

## Release Date

2026-11-24

## Overview

`deleteTaskChain` can delete without forcing, so Datasphere refuses while something uses the chain. The client also says which such behaviours it has (`capabilities`). Catalyst-CLI v2.8.0 uses both to prune task chains in `catalyst bdc deploy`.

## Breaking Changes

None. `deleteTaskChain(name)` still sends `deleteAnyway=true`. The options argument is optional.

## What's New

### Deleting a task chain without forcing

`deleteTaskChain(name, { deleteAnyway: false })` sends `deleteAnyway=false`. With no options it still sends `deleteAnyway=true`, as before.

### `client.capabilities`

A read-only list of what a build can do that a caller cannot tell from a method's presence. `'task-chain-delete-options'` means `deleteTaskChain` honours `{ deleteAnyway }`; an older build ignores the options and forces. Exported as `CLIENT_CAPABILITIES` and `ClientCapability`.

The non-forced task chain delete has not been run on a tenant.

## Technical Details

- `core/operations/task-chain/delete.ts`: an optional `DeleteOptions`, as `sql-view/delete.ts`.
- `client/types.ts`: `CLIENT_CAPABILITIES`, `ClientCapability`, `BdcClient.capabilities`, `deleteTaskChain(name, options?)`. `client/client.ts` implements both.
- Tests: new unit test `capabilities.test.ts`. The existing `tokenCache.test.ts` case "leaves valid JSON and no temp files behind" fails on this machine with and without this change.
- Docs: `api.md`. Changelogs v0.4.0 and v0.5.0: their commits are listed.
